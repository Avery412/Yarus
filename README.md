# ЯРУС — складской учёт стройматериалов

React-интерфейс для каталога товаров, справочника складов, остатков и журнала. Rails обслуживает маршруты, сессии и формы. PostgreSQL хранит остатки и неизменяемые складские движения.

## Запуск

Нужны Ruby 4.0.9, RubyGems и Bundler 4.0.20, Node.js 22 или новее и PostgreSQL 18.6. Настройте подключение через параметры из [шаблона окружения](.env.example). База по умолчанию называется `yarus_development`, тестовая — `yarus_test`. Данные подключения берутся из переменных процесса. Windows-скрипт проверки также читает локальный `.env`.

```sh
bundle install
npm ci
npm run build
bundle exec rails db:prepare
bundle exec rails server
```

Откройте [локальное приложение](http://localhost:3000/). Для пересборки React во время разработки запустите `npm run watch` в отдельном терминале.

### Учётная запись и демонстрационные данные

Установите `YARUS_DEMO_PASSWORD` в текущем сеансе терминала (от 12 символов, не более 72 байт) и выполните `bundle exec rails db:seed`. По умолчанию создаётся `operator@example.test`. Адрес можно задать через `YARUS_DEMO_EMAIL`. Демонабор содержит два товара, два склада и три операции. Повторный запуск сохраняет существующий пароль и не дублирует демонстрационные операции.

Для обычного рабочего контура учётную запись создаёт администратор развёртывания в `bundle exec rails console`. Пример интерактивного ввода без пароля в истории команд:

```ruby
require "io/console"
User.create!(email: "operator@example.test", role: :warehouse_operator, password: $stdin.getpass("Пароль: "))
```

Автор операции берётся из активной сессии. Складские разделы доступны после входа. Роли `manager` и `warehouse_operator` отображаются в интерфейсе и используют одинаковый набор складских действий до внедрения политик из приложения А ТЗ.

## Как устроен интерфейс

- Обычные Rails-маршруты передают React только поля текущего экрана. ERB содержит точку монтирования и данные, а React отрисовывает страницы, формы и навигацию.
- Формы отправляются на тот же origin с Rails CSRF-токеном. Ответы 422 возвращают введённые значения и ошибки. Успешные операции открывают сохранённую запись.
- Товары и склады можно создать, просмотреть и изменить. Остатки и журнал поддерживают поиск, фильтры и серверную пагинацию.
- Приход и расход проходят через `StockMovements::Create`. Он управляет транзакцией, блокировкой остатка и записью в журнал. Для исправления записи есть переход к форме обратной операции.
- В основе интерфейса согласованная палитра, Inter, фотография и иконки материалов из [дизайна ЯРУСА](https://www.figma.com/design/aqaRWrz7TmX9Dsv2uCTqES).

Подробности исходной серверной архитектуры описаны в [документации бэкенда](BACKEND_IMPLEMENTATION.md).

## Проверка

```sh
npm ci
npm run build
RAILS_ENV=test bundle exec rails db:prepare
bundle exec rails zeitwerk:check
bundle exec rails test
bundle exec rails test:system
```

Для системного теста нужны Chrome и ChromeDriver (Selenium Manager подбирает драйвер). GitHub Actions выполняет сборку и проверки на PostgreSQL 18.6. На Windows можно запустить `scripts/verify_backend.ps1` из PowerShell после установки PostgreSQL, Node.js и RubyInstaller с DevKit. Скрипт проверяет версии, базы, сборку React и запускает обычный набор Minitest.

`docker build -t yarus .` собирает React и компилирует Rails-ресурсы внутри образа. Для запуска укажите подключение к PostgreSQL и `SECRET_KEY_BASE`, передав секрет через окружение развёртывания. Production рассчитан на HTTPS.

Проверка на защите: создать товар и склад, оформить приход 10, затем расход 3,25. Открыть остаток 6,750 и попытаться списать 7. Форма должна сохранить количество, а журнал — две проведённые записи с автором и временем.
